# 南京核心六区空间数据 / Nanjing Atlas 09

本版按用户指定的鼓楼、玄武、秦淮、雨花台、建邺、栖霞六个行政区扩展空间研究范围。六区边界及建筑、道路、用地、水体、具名设施和服务参考点均来自实际 OpenStreetMap 对象；没有生成虚构的城区、街道、建筑、地籍宗地或土地交易记录。

## 来源、范围与日期

数据源为 OpenStreetMap，经 [Overpass API](https://overpass-api.de/api/interpreter) 分区检索。源数据时点为 **2026-09-12 06:54:05–06:58:05 UTC**；准确的各区时点、对象数及区域缓存时点见 `dist/data/manifest.json` 的 `sourceSnapshots`。这是开放地图数据库快照时点，不是对象的实测或建设日期。区界单独下载并验证为六个完整面对象，未将六区误写成一个行政区。

表中数量是本次开放地图收录量，不是官方普查总量。建筑含部件，不能理解为独立栋数；道路等线对象包含分段道路、轨道及线状水系，不能理解为道路条数；用地轮廓和用途标签不是地籍或法定现状用地资料。

检索保留与区界相交对象的完整几何，并以 `node/`、`way/`、`relation/` 加 ID 去重，没有沿区界切断跨区建筑或道路。每个对象的 `division_code` / `district_name` 优先采用包围盒中心所在行政区；中心不在六区内的相交对象按检索区记录，并用 `district_method` 说明。原始检索所属区保留在 `query_district_codes`。该分区仅用于检索和界面组织，不是权属或精确面积归属。同一跨区对象不在分区表内重复计数，因此玄武分区的分配计数不能与上一版独立玄武区相交检索数量直接相比。

全部坐标为 **WGS84 / EPSG:4326**。六区边界总范围为 `[118.5843581, 31.8676515, 119.2395068, 32.2470622]`；栖霞区包含行政范围内的滨江、岛屿和东部区域，并不只保留已经建成的城市街区。周边数据稀疏或缺失可能来自制图覆盖差异，不能用于推断没有建筑、设施或开发需求。

## 三维建筑与地形

- 9,658 个地上建筑或部件具有可解析的 OSM `height`，标记为 `height_source: "osm"`；这表示来源标签存在，未经测绘复核。
- 2,008 个按 `building:levels × 3m` 推算，标记为 `levels`。
- 34,849 个高度未知，事实字段 `height_m` 保持 `null`；`render_height: 12` 仅供三维示意，不当作测量高度，也不用于实际容积率或建筑面积计算。
- 排除 147 个地下或室内建筑对象。转换时未发现 tainted / 缺失几何对象；几何 QA 不等于专业测绘拓扑验收。

独立检查发现 8 个建筑源多边形存在共 9 处严格自交：OSM way `448907846`、`1304191049`、`1312713795`、`1370374176`、`1396478930`、`1408186348`、`1425969376`、`1426031035`。保留原始坐标，未自动修补或将这些对象用于精确建筑面积计算。六区边界、用地、水体和研究范围未在该项环自交检查中发现问题，但不据此宣称完成所有 OGC 拓扑有效性验证。

本次沿用的同站 Terrarium DEM 仍覆盖上一版玄武区及邻近范围，未宣称六区已全部具有精确地形。扩大行政范围不意味着获得了高德卫星影像、建筑精模或倾斜摄影；本版没有调用高德接口或抓取其瓦片。

## 用地研究与设施参考点

保留 `XW-R01` 至 `XW-R08`，新增 `GL-R01` 至 `GL-R04`、`QH-R01` 至 `QH-R04`、`YH-R01` 至 `YH-R04`、`JY-R01` 至 `JY-R04`、`QX-R01` 至 `QX-R04`。新增范围均选自本次下载的具名 OSM 用地或公共设施多边形，原始 ID、名称、几何和来源链接均保留。新增示例面积介于 1,000 和 2,000,000 平方米之间，参考中心位于对应区界内。研究类型描述展示关注方向，不能当作法定用途判定。

这些对象用于展示单元选择、设施联系、价值画像、情景推演和报告流程。列入研究清单不表示被认定为低效、闲置或拟实施更新。演示业务台账继续单独标注为虚构，不因研究边界来自真实地图而成为真实调查结果。

服务点包括交通、教育、医疗、公园、历史要素与生活服务。节点保留实际坐标；面和线对象使用包围盒中心，并明确注明不是入口。相同分类、同名且相距 80 米以内的对象合并，保留全部 `related_osm_ids`；不同名称的同址设施可能仍重复。交通点位未核验实时运营，设施数量也不代表床位、学位或服务容量。距离分析为直线距离，不解释为步行时间或法定服务标准。

`value-evidence.json` 中的五篇公开案例/规划资料及两笔历史成交参考保持既有来源与日期，内容仍以玄武区为主。新增 `coverage` 字段明确区分六区空间覆盖与既有业务资料的地理范围。本次没有虚构新增区的市场交易、权属、空置率或经营台账；尚不足以建立正式地价评估模型。

## 文件与复现

空间层文件名与旧版兼容：`boundary.geojson`、`buildings.geojson`、`roads.geojson`、`land.geojson`、`water.geojson`、`pois.geojson`。设施与研究仍为 `services.geojson` 和 `research-units.geojson`。清单新增 `districts`、`divisionCodes`、`sourceSnapshots`、`snapshotRange`、`districtNote`、`researchUnitCount` 及 `serviceCount`。单一 `divisionCode: "320100"` 表示南京市研究上下文，实际范围必须以六项 `divisionCodes` 为准，并不表示已覆盖南京市所有行政区。

```bash
python scripts/fetch-nanjing.py /tmp/nanjing-raw
node scripts/prepare-nanjing.mjs /tmp/nanjing-raw
npm run build
```

下载脚本优先复用已经成功的原始响应，默认顺序请求；可显式使用 `--workers 2`，最多两个请求并行。每个地物查询服务端时限 110 秒，客户端时限 135 秒；区界更短。任何 Overpass `remark`、空结果或网络错误都会失败并记录，不会将超时或截断响应作为完整数据。本次两个区曾返回 HTTP 429，停止该轮后仅重试缺失区并顺序完成，未绕过限流。完整查询文本及下载日志保存在指定原始数据目录中，运行时不依赖 Overpass。

处理脚本校验六个完整边界、逐区非空响应、研究对象实际存在与空间范围，统一分类并按原始 ID 去重。更新前后均需重新验证计数、原始 ID、高度缺失和研究单元，再运行项目检查及打包。
