# Studio 13 评估依据与报告

本次对应路线第三步。主入口保持 https://zipan07.github.io/UrbanLens/ ，私有项目服务使用已有 https://urbanlens-workbench.zipan07.chatgpt.site 。

## 操作顺序

1. 选地：地图或清单选入研究单元。
2. 核对资料：原始值、单位、来源、日期、有效性与人工核实；规划、权属、安全单独核对。详细档案、周边设施和容量情景折叠展示。
3. 运行评估：选择数据口径和演示权重，保存当前数据版本结果。资料不足可保存缺项结果，但不合成总分。
4. 复核报告：按登录账户记录复核结论、意见与时间，再预览、保存与导出。

比较支持 2–3 个单元、历史运行、差值基准、只看差异、约束对照、逐项回源和固定比较快照。缺项或口径不一致时不排序。

## 数据与权限

逐项依据与约束进入新的项目数据版本。字段依据绑定原始值、数据模式、底层来源日期和几何；数值或模式变化后，旧核实状态不套用新数据。约束绑定几何，边界变化后回到资料不足。旧运行固定保存原始值、来源、规则、空间分析和约束；旧报告不覆盖。

复核使用现有项目权限，查看者不可提交。复核身份和时间来自服务端。新报告的计算、来源和复核章节由后台根据已保存运行及最新复核重建，客户端只提交研究叙述和地图快照；导出使用保存后返回的报告。

已有数据库结构可容纳本次新增的 document / review 记录，不修改已应用的初始迁移。项目存储与授权仍由 D1 / R2 和现有认证负责。

## 附件依据

单个 PDF / TXT 最多 5 MB。TXT 使用 UTF-8，分页符划分页，无分页符按第 1 页。PDF 使用随站分发的 PDF.js 5.6.205 legacy build 和 CJK 字符映射提取文本，最多 200 页、150 万字符；按页保存索引和原始文件 SHA-256。PDF 客户端提取文本标注待对照原文，未提供 OCR，不把空白提取结果当成无事项。

附件页可用于字段、约束、比较和报告引用；证据问答输入“附件 + 关键词”检索项目内原文。无命中时明确说明。旧版已上传但无页索引的附件仍可下载，重新上传后生成页索引。

## 原网址与项目连接

GitHub Pages 托管完整网页，不运行后台 API。点击“连接项目”打开已认证的私有工作区窗口，在窗口内确认后，以严格限定 origin、opener、随机通道和 API 路径的消息协议操作项目。认证凭据不转移，项目权限仍在后台逐项检查。连接窗口需保持打开；浏览器若通过 COOP 或登录流程切断窗口关系，可直接进入云端工作区。此发布不改变现有私有受众。
