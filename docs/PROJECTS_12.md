# Studio 12：项目、数据版本与权限

本次以 Studio 11 的玄武地图和五维评估界面为基础，在既有 UrbanLens Site 接入 Worker、D1 与 R2。带后台的工作区入口：https://urbanlens-workbench.zipan07.chatgpt.site 。此前的 GitHub Pages 静态站保持原有发布，不能承担后台持久化。

## 产品行为

- 项目列表、新建（玄武 8 个公开研究轮廓 / 空项目）、进入、归档、恢复归档。
- 项目绑定边界、台账、附件、评估、报告、比较及研究记录。初始项目仅创建者可见。
- GeoJSON / CSV 的字段映射、平方米/公顷及比例/百分数单位映射、后台预检、逐行错误、原始内容预览及整批提交。
- 相同 parcel_id 的冲突必须明确选择生效来源；旧来源、导入来源、原文件与决策一起保存。选择导入行也采用其中空值。
- 每次边界/台账修改或恢复历史都产生新的数据版本；历史结果保留其原始输入、边界、规则和操作者，不随当前数据改变。
- PDF / TXT 附件由服务器核对项目权限后下载；最多 5 MB。数据导入最多 8 MB、1,000 条。
- 管理员可管理成员及归档；编辑者可修改项目资料；查看者只读。身份来自平台认证头，角色来自服务端项目成员表。代码中没有可自行切换身份的角色演示开关。
- 成员需先获得本站访问权限并登录一次，再由项目管理员使用其账户编号分配项目角色；本站访问与具体项目授权分别生效。
- 横向比较支持 2–3 个地块，添加/移除/清空、基准、排序、仅看差异、五维与原始指标、边界示意、地图定位、CSV / JSON 及固定运行快照保存。
- 历史比较使用同一地块两次已保存评估；保存基准运行编号，差值和说明一致。规则或口径不一致时不解释分数升降；缺失值不按零计算，比例差用百分点。
- MapLibre 滚轮速率改为 1/180，连续缩放速率 1/70；Canvas 缩放系数从 .002 提高到 .006。中键旋转和触控板旋转保留。

## 存储与一致性

逻辑绑定：`DB`（D1）、`BUCKET`（R2）。结构定义在 `db/schema.ts`，由 Drizzle 生成的初始迁移位于 `drizzle/`。发布只应用迁移，运行时不创建或改表。

D1 保存项目、成员、数据版本索引、记录索引、预检令牌和操作历史。R2 保存版本化数据、原始导入与冲突、评估快照、报告和附件。所有读取均从所属项目授权开始；R2 键由服务器生成，不接收客户端任意对象键。

每次写入携带预期项目 revision；同一项目 revision 的事件唯一约束和 D1 事务批处理防止静默覆盖。正式数据与审计记录一起提交。导入令牌限定项目和操作者，60 分钟有效，成功提交后的重复请求复用完成结果。归档项目服务端拒绝写入。

前端项目切换检查待保存状态并阻止写入期间切换；异步响应检查项目及会话编号。报告和附件列表刷新不能单独前移写入 revision。角色撤销后后续请求重新校验权限。

## 验证与界限

`test/project-api.test.js` 使用真实 SQLite 事务和磁盘对象存储适配同一服务端处理函数，覆盖认证、项目隔离、所有查看者写入口、成员管理、字段/单位映射、错误整批阻断、来源冲突、幂等提交、并发版本、不可变评估/报告、跨项目引用、恢复历史、归档、撤销授权、基准保存、报告系列编号、异常状态拒绝以及重开存储后的完整性。

保留现有地图、规则、报告和手势测试。测试适配器不替代真实两台设备和实体鼠标的人工验收；本次未声明完成设备实测。当前地图与导入空间范围仍为玄武区。演示评估规则没有升级为经业务核准的正式规则。复杂孔洞拓扑、法定边界与权属仍需专业复核。

浏览器旧版已有的本机记录没有自动迁移到不同域名的新工作区；之前下载的报告继续可用。此后项目记录以后台为准。新的浏览器账户需要被授予相应项目权限，不能因为能看到网站就访问全部项目。
